ChronoAI

An intelligent scheduling agent driven by natural text parsing engines that maps command prompts to active database calendar records and alerts clients in real-time.

Latency: 60% Reduction Real-time WebSockets

1. The Problem

Interfacing with calendar tools through standard GUI forms creates user friction. Conversely, using deep transformer models to resolve natural language triggers is resource-intensive, introducing critical computation delays and requiring expensive GPU servers. An optimized scheduling framework must resolve temporal expressions, verify database records, and sync multi-client dashboards instantly.

2. My Approach

I built ChronoAI using the asynchronous execution model of FastAPI in Python. To eliminate transformer dependency, I engineered a highly optimized rule-based semantic NLP engine. This engine extracts time, date, action, and subject metrics using structured regex loops and pattern arrays. Scheduled events are stored in a MongoDB database, and active alerts are dispatched instantly to clients via raw WebSocket loops.

4. Key Challenges & Resolutions

Challenge: Commands like "schedule meeting next Monday at 3 PM" or "reschedule for tomorrow" are relative to the client's local execution timezone.
Resolution: Engineered relative timestamp resolution modules that accept client-side timezone offsets. The NLP engine calculates standard UTC timestamps before committing updates to MongoDB.

Challenge: Maintaining long-lived WebSocket connections for hundreds of concurrent users could block single-threaded loop operations.
Resolution: Leveraged FastAPI's native async/await syntax to handle connection states non-blockingly, achieving sub-50ms push broadcast latency across all open web sockets.

5. Results & Metrics

  • 60% Latency Reduction compared to transformer-based calendar schedulers.
  • Sub-50ms Event Dispatch times using WebSockets broadcast queues.
  • 92% Accuracy in parsing time-intent parameters from unstructured sentences.
  • Stateless async loop capable of sustaining hundreds of concurrent socket streams.
